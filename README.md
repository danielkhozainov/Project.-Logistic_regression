# Прогнозирование оттока клиентов для сервиса доставки кофе

## Введение

На рынке доставки кофе привлечение нового клиента обходится в 5–7 раз дороже, чем удержание существующего. Сервис **Happy Beans Coffee** ежемесячно теряет около 10% клиентской базы, что напрямую снижает выручку и делает маркетинговый бюджет неэффективным — он «работает вхолостую», не обеспечивая прироста клиентской базы.

Проект решает задачу бинарной классификации (обучение с учителем): для каждого клиента в начале месяца модель рассчитывает вероятность его оттока в течение этого месяца. Ранжирование клиентов по степени риска позволяет службе удержания сфокусировать ресурсы — персональные предложения, скидки, опросы — на наиболее «рисковой» группе.

---

## Цель работы

| Уровень | Формулировка |
| --- | --- |
| **Бизнес‑цель** | Снизить отток клиентов и оптимизировать маркетинговые расходы за счёт своевременного и целенаправленного удержания клиентов, склонных к уходу. |
| **ML‑цель** | Построить модель, которая для каждого клиента в начале месяца рассчитывает вероятность его оттока в течение этого месяца. |

**Ожидаемый выход модели:** вероятность принадлежности к классу 1 (отток) для каждого клиента. Это позволяет не только бинарно классифицировать, но и ранжировать клиентов по степени риска.

---

## Метрики качества

Из‑за сильного дисбаланса классов выбор метрик критически важен.

| Метрика | Роль | Целевое значение | Обоснование |
| --- | --- | --- | --- |
| **PR‑AUC** | Основная | Максимизировать | Фокусируется на качестве предсказания положительного класса (уходящих клиентов), не зависит от доли отрицательного класса. |
| **ROC‑AUC** | Дополнительная | > 0.9 | Показывает общую способность ранжировать клиентов. При дисбалансе может давать излишне оптимистичную оценку. |
| **Confusion Matrix** | Интерпретация | — | Визуализация TP, FP, TN и особенно FN (клиент ушёл, модель не предупредила). |

**Отвергаемые метрики:** Accuracy — бесполезна в условиях дисбаланса классов.

## Данные

### Общие сведения

| Параметр | Значение |
| --- | --- |
| Источник | `coffee_churn_dataset.csv` |
| Размер | 10 450 строк × 27 столбцов |
| Период агрегации | Последние 4 недели |
| Формат | Готовая аналитическая витрина (одна строка — один клиент) |
| Типы данных | 16 полей `float64`, 10 полей `object`, 1 поле `int64` (target) |
| Пропуски | Практически во всех полях |
| Аномалии | Отрицательные значения (до −2290), необъяснимо большие выбросы |

| `total_spent_last_month` | float | Сумма заказов за последний месяц |
| `total_spent_last_week` | float | Сумма заказов за последнюю неделю |
| `discount_usage_rate` | float | Доля заказов со скидкой за последний месяц |
| `last_coffee_type` | object | Сорт кофе из последнего заказа |
| `preferred_roast` | object | Предпочитаемый тип обжарки |
| `milk_preference` | object | Предпочитаемый тип молока |
| `seasonal_menu_tried` | float | Пробовал ли сезонное меню (0/1) |
| `coffee_bean_origin` | object | Страна происхождения зерна |

| `review_rating_last_10` | float | Средняя оценка последних 10 заказов |
| `review_rating_last_1` | float | Оценка последнего заказа |

### Целевая переменная

`churn` — бинарный признак:
- **1** — клиент ушёл (положительный класс)
- **0** — клиент остался (отрицательный класс)

Сильный дисбаланс классов: доля положительного класса — около 6%.

## Ключевые этапы пайплайна

### 1. Предобработка данных
- Обработка пропусков во всех полях (медиана для числовых, константа / мода для категориальных).
- Удаление или корректировка аномалий (отрицательные значения `total_spent_last_week`, `order_frequency_week` и др.).
- Масштабирование числовых признаков (`StandardScaler`).
- Кодирование категориальных: `OneHotEncoder` для низко-кардинальных, `TargetEncoder` для высоко-кардинальных.

### 2. Разделение данных
- `train_test_split` со `stratify=y` для сохранения пропорций классов.
- `StratifiedKFold` для кросс-валидации.

### 3. Защита от утечки
- `TargetEncoder` применяется только на обучающей части внутри пайплайна.
- Все преобразования инкапсулированы в `Pipeline` и `ColumnTransformer`.

### 4. Инжиниринг признаков
- Производные отношения (например, `total_spent_last_week / total_spent_last_month`).
- Взаимодействия признаков (например, `days_since_last_order × order_frequency_month`).
- Отбор через `SelectFromModel` на основе важности логистической регрессии.

### 5. Подбор гиперпараметров
- `GridSearchCV` с оптимизацией по `average_precision_score` (PR-AUC).
- Перебор регуляризации, типа кодирования, стратегий импутации.

### 6. Финальная оценка
- Расчёт PR-AUC и ROC-AUC на тестовой выборке.
- Построение confusion matrix.
- Анализ важности признаков.
- Сохранение модели через `joblib`.

## Практическое применение

Модель встраивается в ежемесячный цикл работы службы удержания CargaPronto Happy Beans Coffee:

1. В начале месяца модель рассчитывает вероятность оттока для каждого активного клиента.
2. Клиенты сортируются по убыванию вероятности.
3. Верхний процентиль (например, топ-5% или топ-10%) передаётся в службу удержания.
4. Для этих клиентов запускаются целевые действия: персональные скидки, опросы, push-уведомления, предложения по подписке.
5. В конце месяца оценивается доля удержанных клиентов из «рисковой» группы.

**Бизнес-эффект:** фокус ресурсов на наиболее рискованных клиентах вместо массовых рассылок снижает маркетинговый бюджет и повышает retention.
